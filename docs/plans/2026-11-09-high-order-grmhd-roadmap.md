## 1. 結論と方針

### 1.1 目標

1. 現行の SF2014 円盤コードの既知の問題を直す。
2. ニュートン MHD の数値スキームを、測定で裏付けられた高精度なものへ置き換える。
3. 3D 基盤を整え、Kerr 時空（固定計量）の GRMHD を実装する。
4. EHT コード比較（Porth et al. 2019）と同じ問題で、公開値と定量比較できる状態にする。

### 1.2 「妥協なし」の定義

機能を全部入れることではない。次の 4 つを指す。

- 主張する精度は、**非格子整列の解析解テストで測った次数**で裏付ける。スキーム名では主張しない。
- 物理解の検証は、**独立した参照**（解析解、厳密リーマン解、他コードの公開値）に対して行う。自コードの旧版との一致は回帰確認にすぎない。
- 非保存の補正（floor、CT エネルギー補正、熱回復）は、すべて台帳に記録して量を報告する。
- 効果が測定で出ない手法は採用しない。実装済みでも既定にしない。

### 1.3 なぜ GRMHD の前に土台を直すのか

- **2.5D のままでは GRMHD の本番計算にならない。** 軸対称では Cowling の反ダイナモ定理により乱流磁場を維持できず、MRI 乱流は減衰する。EHT 比較も 3D である。つまり 3D 化、ひいてはデータ配置と CT の一般化が先に必要になる。
- 現行の Ψ ベース CT、`p.spherical?` 分岐、固定 RK3、AoS は GR 以前に 3D で詰まる。
- 既存テストはスキームの差を検出できていない（2.2 節）。この状態で高次手法を入れても、効いたかどうか判定できない。

### 1.4 自作する理由と限界（minami 判断事項 D1）

AthenaK、KHARMA、iharm3D など成熟した GPU 対応 GRMHD コードがすでに存在する。既存の比較メモ（`gpluto_comparison_20261109.md`、リポジトリ外）も、汎用基盤へ広げる負担を指摘している。
それでも自作する価値があるのは、**受理ステップ単位の輸送台帳と補正台帳**という PyHMD の強みを GRMHD に持ち込める点と、スキームを自分の手で検証できる点である。
これらの既存コードは比較対象として使う。性能や機能の規模で競うことを目標にしない。

### 1.5 スキームの到達目標

| 対象 | 既定の到達目標 | 位置づけ |
|---|---|---|
| ニュートン、Cartesian | FV4 + PPM4 + HLLD 流束 + HLL 型 UCT + 5 段 SSP RK4（Felker & Stone の構成） | 形式 4 次を実測で確認。UCT-HLLD との組み合わせは比較実験 |
| ニュートン、球面（SF2014） | 極値保持 metric PPM または WENO5-Z + HLLD + UCT-HLLD + SSP-RK3 | 高次再構成と面中心流束。多次元の形式次数は 2 次 |
| 球面 FV4 | WP3.4 に合格した場合のみ既定候補 | 研究課題。原論文は一様 Cartesian 格子のみ |
| GRMHD | 極値保持 PPM または WENO5-Z + HLLD（局所系）+ Gardiner & Stone 2005 型 CT + SSP-RK3 | 低拡散を狙うが、効果は測定で確認する。UCT-HLL は比較対象 |
| GRMHD FV4 | 範囲外（Phase 7 で判断） | 確立した手法として扱わない |

Porth et al. 2019 の参加コードは LLF または HLL に PPM（一部 PLM）の組み合わせが中心で、多くは時間 2 次である。
GR の HLLD と CT は White et al. 2016 に実績がある。ただし同論文の EMF は Gardiner & Stone 2005 の拡張で、再構成は PLM である。したがって GR の最初の EMF は GS05 型にし、再構成を PPM 系へ上げる効果は別途測定する。
相対論版 UCT-HLLD の係数は確認した範囲では見つかっていない（Mignone & Del Zanna 2021 は「拡張可能」と述べるのみ）。HLLD の流束と UCT-HLL の EMF を組み合わせても、誘導方程式には HLL 相当の拡散が残るので、「低拡散」は主張できない。

## 2. 現状の基準値（実測）

2026-11-09 に `671fdf6` 相当の `build/pyhmd_cpu`（macOS arm64、Apple Clang 21）で測定した。測定スクリプトは WP0.2 で正式なテストとして作り直すこと。

### 2.1 収束次数

円偏光 Alfvén 波、振幅 0.1、`nx2=4`、t=1（1 周期）、CFL 0.4。誤差は Bθ, Bφ, vθ, vφ の平均。

| nx1 | L1 誤差 | L1 次数 | L∞ 誤差 | L∞ 次数 |
|---|---|---|---|---|
| 32 | 1.1448e-03 | - | 3.184e-03 | - |
| 64 | 2.5682e-04 | 2.16 | 1.077e-03 | 1.56 |
| 128 | 5.1161e-05 | 2.33 | 3.581e-04 | 1.59 |
| 256 | 9.4151e-06 | 2.44 | 1.145e-04 | 1.64 |
| 512 | 1.7144e-06 | 2.46 | 3.605e-05 | 1.67 |

L∞ 次数が 2 未満なのは、limiter が滑らかな極値を削る典型的な症状である。
**この問題は y 方向に不変で実質 1D である。** 多次元の基準値にはならない（WP0.2 で別に測る）。

Brio–Wu（`nx2=4`、t=0.1）の ρ の L1 誤差は、自己参照 2048 セルに対して次の値。衝撃波問題なのでほぼ 1 次は期待どおり。これは厳密解に対する検証ではない。

| nx1 | L1 誤差 | 次数 |
|---|---|---|
| 128 | 6.265e-03 | - |
| 256 | 3.245e-03 | 0.95 |
| 512 | 1.790e-03 | 0.86 |

### 2.2 既存テストの盲点

上の Alfvén 試験で `corner_hll` と `face_hll` の誤差は**全解像度で表示桁まで同一**だった。波が格子に整列していて、EMF スキームの差が表に出ないためである。
`tests/verify.py` の合格条件も `error_ratio < 0.9` だけで、次数を保証しない。多次元の精度はこの試験では測れていない。

### 2.3 静水圧円盤の平衡維持

磁場なし（`mu0=0`、`eta=0`、冷却なし、`thermal_recovery=off`、`initial_equilibrium=hydrostatic`）で t=1、3≤r≤10。

|---|---|---|---|---|
| 150×32 | 1.59e-02 | 1.59e-02 | 7.21e-02 | 1.78e-02 |
| 300×64 | 6.40e-03 | 5.87e-03 | 1.29e-01 | 5.71e-02 |
| 600×128 | 2.20e-03 | 1.50e-03 | 1.78e-01 | 1.88e-01 |

円盤内部は解像度とともに減る（max|vθ|/cs はおよそ 1.3〜1.5 次）。一方、**円盤表面を含めると解像度を上げても誤差が増え、収束しない**。円盤とコロナの接続面が初期条件に含まれる不連続であることが有力な原因だが、切り分けは済んでいない（WP1.4）。

### 2.4 時間刻みの制約

| 150×32 | 0.11 | (2, 26) |

## 3. 作業規則

`AGENTS.md` と `.agents/skills/pyhmd-develop/SKILL.md` に加えて、次を守る。

1. **構造変更と数値変更は別コミットにする。** 構造変更は凍結バイナリとのビット一致で検証する。数値変更は独立した参照で検証する。
2. **旧スキームを残す。** 新手法は設定で選択し、旧手法と比較できるようにする。既定の変更は該当 Gate 合格後に、独立したコミットで行う。
3. **実装した機能だけを登録する。** `--describe`、Python の `Config`、ネイティブ検証、プリセット、テストを同時に更新する。未対応の組み合わせは拒否し、黙ってフォールバックしない。
4. **新しい数値オプションは必ず `io/checkpoint.hpp:20` の `signature()` に加える。** 再開の互換性を崩す変更では `revision` タグを更新する。
5. **他コードのソースを複製しない。** 論文から実装する。既存コード（PLUTO、Athena++、KHARMA など）とは出力の比較に留める。ライセンス確認なしに取り込まない。
6. **CPU の結果で GPU や MPI の動作を主張しない。** 検証した環境を証拠 JSON に記録する。
7. **ジョブ投入、push、PR、公開は minami の明示的な許可を得てから行う。** クラスタの接続情報はコミットしない。
8. **各 WP の完了報告に含めるもの:** 変更内容、実行したコマンド、測定値、未検証の項目。「完走」「数値的整合」「科学的再現」を区別して書く。
9. **証拠の置き場所:** 測定結果は `docs/validation/<wp-id>.json` に置き、再現コマンドを含める。大きな出力はコミットしない。
10. **文書:** ユーザー向けの `docs/*.md` は英語と日本語を同時に更新し、`python3 scripts/check_docs.py` を通す。
11. **CPU と GPU の一致基準:** 同じ状態からの 1 回の RHS で、ステンシルのスケールに対する相対差 1e-12 以内を初期値とする。100 ステップ後の差も記録し、WP0.4 のノイズフロアと比較する。値を変える場合は根拠を残す。
12. **長時間計算のバイナリ凍結:** ソース fingerprint は `signature()` に含まれるので、ソースを 1 行でも変えると再開できなくなる。長時間計算を始めたら、その世代のバイナリとソースを固定し、計算中のコード修正は別の世代として扱う。この制約を緩めない。

## 4. 全体の流れ

```text
Phase 0 計測と検証基盤（ビット一致）
   ├── Phase 1 SF2014 内側境界と物理整合（現行 2.5D のまま、並行可）
   └── Phase 2 構造の再設計（ビット一致）
          └── Phase 3 高精度スキーム（ニュートン）
                 └── Phase 4 3D MHD、MPI、I/O
                        └── Phase 5 SRMHD
                               └── Phase 6 GRMHD
                                      └── Phase 7 拡張（各項目を個別に判断）
```

| Gate | 通過条件の要点 |
|---|---|
| G0 | 次数ハーネスが動き、凍結バイナリが保存され、GPU 検証手順がある |
| G1 | 内側境界の機構が定量的に説明され、SF2014 との差の表が更新された。再現の成否は問わない |
| G2 | 全構造変更が拡張した移行テスト（WP0.1）で凍結バイナリとビット一致（CPU）。GPU は規則 11 の基準内 |
| G3 | 8 章末の数値目標を達成。低 β 衝撃波が棄却なしまたは局所処理で通る |
| G4 | 3D 斜め波で次数を維持。分割数によらず結果が一致。3D 球面の極を越えるテストに合格 |
| G5 | SR 衝撃波管の厳密解に対する誤差と、con2prim の WP5.1 の目標を達成 |
| G6 | Porth 2019 の問題で 11 章の判定を行い、結果の表を残す |

Phase 1 が再現未達でも Phase 2 以降は止めない。ただし SF2014 の再現を主張してはならない。

規模の目安は S（数日）、M（1〜2 週間）、L（数週間）、XL（1 か月超）で、人手換算の粗い見積もりである。

## 5. Phase 0: 計測と検証基盤（規模 M）

現行の数値結果を変えない。

### WP0.1 基準バイナリの凍結

- CPU、MPI、CUDA（SM70、SM80、SM90 のうち使えるもの）の現行バイナリを、リポジトリ外に保存する。SHA256、fingerprint、コンパイラ情報を記録する。
- 再ビルドで基準を作らない（SKILL の規定どおり）。
- **既定ビルドと FP 厳密ビルド（WP0.4）の両方を凍結する。** 既定の FP フラグは G2 完了まで変更しない。Makefile は今 `-ffp-contract` を指定していないので、フラグの変更そのものがビット一致を壊す。
- `configs/` も凍結する。今の `verify_migration.py` は候補側のツリーから INI を読むので、プリセットの変更に気づけない。

`scripts/verify_migration.py` を拡張する（現状は CSV、U、Ψ、時計だけを比較し、5 小格子と 600×128 の 100 ステップのみ）。

- 比較対象に**全台帳**（`floors`、`thermal`、`flux_accounting`、輸送 sidecar）と `diagnostics.csv` を加える。
- 対象の構成に、非既定スキーム、`transport_diagnostics=yes`、MPI 2 rank と 4 rank、**実際にロールバックとリトライが起きる入力**、再開を加える。発生したことをテスト内で確認する（`rejected_steps>0` など）。
- バイナリのオフセット決め打ちをやめ、checkpoint のスキーマに応じたパーサにする（WP2.1 の v2 に対応するため）。

**合格:** 拡張後のテストが、保存済みバイナリに対して自分自身とビット一致する。さらに、故意に 1 箇所変えた候補を検出できることも確認する。

### WP0.2 次数測定ハーネス

新設 `tests/convergence/`、`make test-convergence`。結果を次数付き JSON で出力する。

追加する問題（プリセット、`Config`、ネイティブ初期化を同時に追加）:

| 問題 | 内容 | 目的 |
|---|---|---|
| `oblique_alfven` | 格子に対して傾いた円偏光 Alfvén 波。厳密解あり | **多次元の EMF 精度の主試験** |
| `linear_wave` | 固有ベクトルから作る fast、Alfvén、slow、entropy の各線形波。斜め方向 | モード別の次数 |
| `field_loop` | 磁場ループの移流（Gardiner & Stone 2005） | CT の拡散と形状保持 |
| `rj2a`、`brio_wu` | 厳密リーマン解との比較 | 衝撃波の位置と振幅 |
| `orszag_tang`、`blast_low_beta` | 非線形と低 β の頑健性 | 既定スキームの回帰 |

- 周期境界で、誤差を保存量と面磁場の両方について L1 と L∞ で報告する。
- 線形波の振幅は、非線形項が次数測定を汚さない値を選ぶ。Felker & Stone 2018 は誤差が振幅の 2 乗程度で頭打ちになると述べている。
- 厳密リーマン解は Torrilhon（ETH SAM Report 2002-06）の方法を独立実装するか、十分細かい別スキームの結果を使う。参照の出所を JSON に記録する。
- **Brio–Wu には非一意性の問題がある。** Torrilhon 2003 は数値解の擬収束を報告しているので、どの解の枝を「厳密解」としたかを記録する。
- **多次元の次数低下を見逃さない。** 高次再構成と面中心流束の組み合わせは、非線形系で多次元では 2 次に落ちる（Zhang, Zhang & Shu 2011）。線形問題では高次のまま見える可能性がある。また、O(h²) の係数は振幅に依存するので、中程度の解像度では高次に見えることがある。したがって `oblique_alfven` を**複数の振幅（0.2、0.1、0.01 など）で高解像度まで**測る。
- **合格:** 現行スキームの基準次数を測定して `docs/validation/baseline_orders.json` に保存する。**ここで測った値が以後の比較の起点になる。**

### WP0.4 浮動小数点の再現性とノイズフロア

既存の調査（`parallel_reproducibility_cfl_analysis_20261109.md`）で、1000 ステップ時点で U の差 4e-13 の世代差が、t=200 の内側 μ で約 2% に成長した。原因は未確定で、FMA や命令順序が候補に挙がっている。

- `-ffp-contract=off`（CPU）、`-fmad=false`（nvcc）のビルドオプションを追加して比較する。既定値は測定後に決める。

## 6. Phase 1: SF2014 の内側境界と物理整合（規模 L）

現行の 2.5D コードに対して行う。Phase 2 と並行できるが、同じ箇所を触るときは Phase 2 の該当 WP の前に片付ける。
背景は `model_consistency_followup_20261109.md`、`transport_resolution_analysis_20261108.md`（リポジトリ外）を読むこと。報告では、内側 μ が t=10000 で約 8460 分の 1 まで低下、内側 corner に大きな UCT 寄与、CFL を半分にしても改善なし、となっている。

### WP1.1 機構の診断

- 内側 corner の EMF を、移流項、UCT の拡散項、ηJφ に分解して保存する。
- ghost セル中心の磁場角も保存する（目標 `Bθ/Br = -tan φ`）。
- **合格:** 内側磁束の減少を、半径帯ごとに各項で閉じて説明する表ができる。これだけでは原因を断定しない。

### WP1.2 磁場境界の候補と比較

現行は Ψ の微分関係を指数型再帰で満たしており（`boundaries/physical.hpp:75`）、セル中心の角度条件とは一致しない。報告された最大角度差は約 9° で、細分化で減らない。

試す候補（`inner_magnetic_bc` で選択）:

| 候補 | 方法 | 注意点 |
|---|---|---|
| `psi_ode` | 現行 | 基準 |
| `cell_angle` | セル中心の条件を厳密に満たす Ψ の離散漸化式 | 下記の振動モードあり |
| `cell_angle_filtered` | 上に奇偶モード抑制を加える | 抑制が境界を変える |
| `ghost_b_only` | Ψ は保ちつつ、再構成に渡す ghost のセル中心 B だけ角度条件で与える | **面流束と信号速度にしか効かない。** EMF の面内 B は Ψ から作られ（`staggered_edge`）、`exchange` が ghost の B を上書きする（`solver.hpp:201`）。その上書きの順序も変える必要がある |
| `emf_prescribed` | 内側 corner の EMF を直接処方する | 力学的な根拠を論文と照合 |

**`cell_angle` の注意:** 条件 `Bθ,c + tanφ Br,c = 0` を代入すると、y=Ψ(i,·) について次の 1 階漸化式になる。

```text
y[j+1] = A[j] y[j] + C[j]
A[j] = (γ - α[j]) / (γ + α[j+1])
α[j] = 1 / (2 area2(i,j)),  γ = tanφ / (2 area1(i,j))
```

軸の面では `area2=0` なので α=0 とする（`field2` の扱いと同じ）。

thin_disk の内側 ghost 列で計算すると、**軸近傍で |A|>1 になるセルがある**（600×128 で j=1〜5、1200×256 で j=1〜6）。赤道付近は |A|≈0.40。α>γ の領域では A が負になり、符号が交代する。`physical.hpp:77-79` のコメントが避けている「符号交代モード」はこれに関係すると読める。
**そのまま実装してはならない。** 固有値ではなく A の累積積で増幅を評価し、単体プローブで格子依存と摂動への応答を調べ、結果次第で候補を落とす。アフィン形式なので GPU の prefix scan（`boundaries/gpu_scan.hpp`）は再利用できる。

**合格:**
- 物理法線面の磁束を保持し、divB が丸め誤差レベルである。
- 角度誤差が細分化で減る。減らない候補は、なぜ許容できるかを説明する。
- WP0.4 のノイズフロアを超える差についてのみ、効果を主張する。

### WP1.3 内側 sink の実流束

ghost の `v_r≤0` では HLL の密度差項による流入を防げない。報告では t=10000 の全期間累積で円盤境界の mass OUT が -1.15/rad となっている。

- 円盤帯の境界面の流束に対する diode オプションを追加し、台帳に記録する。
- **合格:** 意図した向きの質量流束が得られる。diode を適用した量と回数を報告する。エネルギーと角運動量の扱いを文書化する。

### WP1.4 初期平衡と円盤表面

- 同じ磁場で `hydrostatic` と `magnetohydrostatic` を比較する。
- 2.3 節の非収束を切り分ける。円盤表面を接続面の不連続として解像度別に調べ、接続を滑らかにした対照実験を行う。**既定は変えない。** 論文の記述に含まれない変更であることを明記する。

### WP1.5 外部比較

- まず解析的な抵抗拡散と Alfvén 波、次に共通状態での 1 回の RHS と境界、最後に円盤の進展という順で gPLUTO と比較する。
- `strong` モデルの音速規約（`Cs=√(p/ρ)` か `√(γp/ρ)`）を対照実験にする。α を黙って変更しない。
- 原著の `init.c` などが未入手である前提を、結論に明記する。

## 7. Phase 2: 構造の再設計（規模 XL）

**この Phase の全コミットは CPU で凍結バイナリとビット一致を保つ。** ここでは数値を変えない。

### WP2.1 データ配置

- SoA の `Field` を導入する（`q(var, i, j, k)` のアクセサ、CPU と GPU 共通）。カーネル内で局所的に `State` へ読み書きする形は維持してよい。
- `NV`、`NG` をモデルとスキームの定数へ移す。`NG` は FV4 で増える。Felker & Stone 2018 の読んだ範囲に具体的な数はないので、ステンシルから導出して検証する。
- `Parameters` は hot な部分と cold な部分に分ける。カーネルへの渡し方（値渡しか、デバイス上の定数バッファか）は `PYMHD_KERNEL_STATS` と実測で決める。
- checkpoint は論理順序で保存し、形式を v2 にする。旧 checkpoint の通常再開は従来どおり拒否する（署名チェックを緩めない）。**形式が変わるので、バイト列の比較ではなく、論理配列の比較で一致を確認する**（WP0.1 のパーサを使う）。

### WP2.2 実行層

- `parallel_for` を 64 bit 化し、3D の範囲指定版を追加する。
- CPU に OpenMP を導入する。`capture_failure` を atomic にし、**どのセルの失敗を記録するかが実行順に依存しないよう、最小インデックスを選ぶ規則**にする。段内で書き込みが競合するループがないか全カーネルを点検する。
- **合格:** スレッド数によらずビット一致（`rate` の集約と失敗レポートも含む）。4 コア以上で速度向上を測定して報告する。

### WP2.3 時間積分の一般化

- `solver.hpp:287-290` の直書き係数を、Shu–Osher 形式の係数表に置き換える。
- 重みは 3 種類ある。RHS の重み、補正の最終状態への寄与重み（`final_weight`）、境界投影の重み（`projection_weight`、`solver.hpp:288`）。**今の RK3 では投影と RHS の重みが同じ値だが、一般の表では同じとは限らない。** それぞれの定義を導出して別々に持つ。
- **浮動小数点の罠:** 状態更新は `w1=1-w0` を使っており、`1-1./3 ≠ 2./3`、`(1-1./3)*.25 ≠ 1./6` である（実測）。ビット一致のため、状態更新の係数は現行の式で計算し、台帳の重みは有理数の値として別に持つ。台帳の重みを更新係数から計算してはならない。
- **合格:** SSP-RK3 で既存の `1/6, 1/6, 2/3` と `1/6, 2/3, 1` が再現され、ビット一致を保つ。加えて、5 段の表を単純な ODE に適用して次数と台帳の閉じを確認する単体テストを置く（RK3 だけのテストでは一般化を検証できない）。

### WP2.4 座標の抽象化

- 面積、体積、辺長、幾何ソースを `Geometry` ポリシーにまとめる（`Cartesian`、`SphericalAxisym`）。
- `p.spherical?` の実行時分岐をカーネルから除く。
- GR の計量を後から追加できる形にする。面と辺の位置で計量を参照する API を、この時点で想定して設計する。

### WP2.5 モデルとスキームのポリシー

- `Model`（基本量と保存量の変換、流束、波速、ソース）と `Riemann`、`Reconstruction` をコンパイル時ポリシーにする。デバイス上で仮想関数を使わない。
- 選択は `evaluate` の入口で 1 回の分岐にまとめる。組み合わせが増えて nvcc のコンパイル時間が悪化するので、TU を分割して明示的インスタンス化する。ビルド時間を測定して報告する。
- nvcc の拡張ラムダの制約（`gpu_optimization.md` にある、コンストラクタ内の起動不可など）を継続して守る。
- `--describe` を `models`、`schemes`、`dimensions` の一覧に拡張し、プロトコルのバージョンを上げる。Python 側も同時に更新する。

### WP2.6 Solver の分割

状態保持、台帳、時間積分、境界交換に分ける。リトライ時に試行中の台帳を確定しない契約と、`rejected_trial_hook` の呼び出し順序を維持する。

**G2:** 拡張した移行テストが CPU でビット一致。GPU は規則 11 の基準内。ステップあたりの実行時間の悪化が 5% 以内。測定は既存のスケーリング試験と同じ方法（同一ノード、I/O なしの区間、step 200〜1100 の中央値、3 回）で行う。超えたら G2 は不合格で、minami の承認があれば先に進める。

## 8. Phase 3: 高精度スキーム（ニュートン、規模 XL）

各 WP は WP0.2 のハーネスで効果を測る。最初は `oblique_alfven` で判定する。

### WP3.0 CT の一般化（面磁場と辺 EMF、`nφ=1`）

**スキームを Ψ-CT の上に作ると、3D 化で作り直しになる。そこで最初に CT を一般化する。**

- 状態を面磁束と辺 EMF で持つ CT を、φ 方向 1 セルの 2.5D で動かす。`Bφ` は φ 面の staggered 量になり、現行のセル中心 FV とは離散化が変わる。
- **Ψ 差分とはビット一致しないので、これは構造変更ではなく数値変更として検証する。** Ψ 経路は回帰用に残す。
- **合格:**
  - 離散 divB が丸め誤差レベル。
  - 全テスト問題で、Ψ 経路との差が基準次数で減少する。
  - 円盤の短時間計算で、Ψ 経路との差がノイズフロア程度か、それを超える部分の説明がつく。

WP3.2 以降はこの層の上に実装する。

### WP3.1 再構成

実装する:

| 名前 | 内容 |
|---|---|
| `ppm_ep` | 極値保持 PPM。Colella & Sekora 2008 と、Felker & Stone 2018 が採用した Colella et al. 2011 §4.3 の変種を比較 |
| `wenoz5` | WENO5-Z（Borges et al. 2008）。不等間隔は Mignone 2014 の方法で重みを作る |
| `mp5` | MP5（Suresh & Huynh 1997） |
| 平坦化 | Colella & Woodward 1984 の flattening を選択可能に |
| 特性変数 | MHD の固有ベクトルによる再構成オプション |

- 球面の重みと曲率係数は `numerics/metric_reconstruction.hpp` の枠組みを拡張する。
- Felker & Stone は一部の MHD 衝撃波管で、振動抑制に特性変数の再構成が必要だったと報告している。
- 磁場の横方向再構成と、EMF に使う速度の再構成も同じ手法にそろえる。
- **合格:** 1D 問題で L∞ 次数 3 以上（基準 1.67）。多次元の目標は 8 章末の G3 に従う。Brio–Wu と RJ2a で全変動の増加を測定し、基準の 1.5 倍以内に収める。

### WP3.2 HLLD と UCT-HLLD

- HLLD（Miyoshi & Kusano 2005）を `Riemann` ポリシーとして実装する。`hll()` の引数を整理し、流束に加えて EMF 用の係数 `(a_L, a_R, d_L, d_R)` を返す形にする。
- EMF は Mignone & Del Zanna 2021 の式 (33) と、HLLD の係数の式 (40)、(42)、(44)〜(46) に従う。退化スイッチの ε=1e-9 も論文どおり。
- `ENTR`、`EINT`、角運動量の扱いを接触波の風上に合わせる。`rf`（抵抗流束）の加算は既存の形を保つ。
- `HllTransport` の分解（移流項と不連続項）と、`EINT` の発散項に使う `interface_velocity` を HLLD の接触波に合わせて定義し直す。**輸送台帳の意味が変わるので文書化する。**
- `Bn→0` と低 β の縮退、負圧の中間状態への対処を実装する。失敗時は WP3.5 の局所フォールバックに接続する。
- **合格:**
  - RJ2a と `oblique_alfven` の同じ解像度で、L1 誤差が HLL の 1/2 以下。
  - HLL 退化時の結果が UCT-HLL と一致する単体テスト。
  - `field_loop` の磁気エネルギーの減衰が HLL より小さい。
  - 円盤問題の棄却数と補正エネルギーの合計が HLL の 2 倍以内。超えたら既定にしない。

### WP3.3 FV4（Cartesian）

Felker & Stone 2018 に従う。

- セル平均と点値の変換を Laplacian 補正で行う（式 6、9）。
- 面平均流束は式 16〜18 の 2 段階で計算する（追加のリーマン解 1 回）。
- EMF は式 36、37、41 と、§4.1.1 の corner 手順に従う（HLL 型の UCT で、流束のリーマン解法とは別に風上化する）。UCT-HLLD との組み合わせは、基本形の合格後に比較実験として行う。
- 面平均磁場からセル中心への変換は式 38〜40。
- 時間積分は同論文の 5 段 SSP 低記憶 RK4（3 レジスタ）。係数は原典から取得して検証する。
- **合格:** `linear_wave` 全モードと `oblique_alfven` で 4 次を実測する（同論文の報告と同じ範囲）。衝撃波問題が破綻しない。

### WP3.4 曲線座標 FV4（研究課題）

Felker & Stone は一様 Cartesian 格子を明示的に仮定しており、対数半径の球面には直接使えない。Colella et al. 2011 の写像格子の枠組みなどを調査する。

- 積分した計量項とソース項の高次精度化、free-stream 保存が必要になる。
- **合格:** 対数半径球面の滑らかな解で 3 次超を実測し、一様状態を丸め誤差で保つ。
- **打ち切り条件:** 上記を満たせなければ既定にせず、「不採用」として結果を文書に残す。**未検証の高次主張はしない。**

### WP3.5 局所フォールバック

今は 1 セルの失敗で全領域が FLAT に落ちる（`solver.hpp:280`）。これを次の階層にする。

1. FOFC（Lemaster & Stone 2009）: 失敗セルの周囲の面だけ低次流束に置き換える。
2. **EMF と面の信号量（`a`、`d`）も同時に低次へ切り替える。** EMF を置き換えると、**印のないセルの B と圧力も変わる**ので、再判定のループが必要になる（回数に上限を設け、超えたら 4 へ）。AthenaK の論文は EMF の扱いを明記していない。実装前に原典を確認し、他コードの方法は出所を記録する。
3. 必要に応じ、Hu, Adams & Shu 2013 型の正値性保持流束制限を追加する。
4. それでも失敗したら、既存の全域リトライと dt 半減に落とす。**最後の手段として残す。**

実装で必要になる変更:

- 失敗の印をセル単位で持つ（今の `capture_failure` は最初の 1 件のみ）。印と低次流束を halo 交換する。
- 輸送台帳は `face_flux_impl` と `face_based_emf` の中で積算しているので、**再計算で二重計上になる。** 積算を最終の流束が確定した後へ移す。
- `face_velocity` と `EINT` の発散項は、最終の流束に合わせる。

**合格:**
- 低 β のブラスト波と円盤の長時間試行で、全域リトライの回数が基準の 1/10 以下になる。失敗の局所性を測定で示す。
- 置き換えた面の数を台帳に記録する。
- FOFC あり、発動 0 回の問題で FOFC なしとビット一致する。
- 再計算ありでも、保存の収支が丸め誤差で閉じる。
- ロールバックの契約（棄却された試行が台帳に残らない）が保たれる。

### WP3.6 エネルギー整合

- CT エネルギー補正なしの保存形と、現行の補正付きを、低 β で比較する。
- `compatible_cooling` と `physical_ohmic` の差の解像度依存を測る。差が収束しない場合は定式を見直す。
- modern 熱回復の衝撃波加熱の誤差を、解析解のある低 β 平行衝撃波で測る（`tests/parallel_shock.cpp` を拡張）。
- **合格:** 各補正の量と、解への影響の表ができる。既定の変更はこの結果に基づいて判断する。

### WP3.7 抵抗項の時間積分

2.4 節より高解像度では抵抗が dt を支配する見込みである。

- RKL2（Meyer, Balsara & Aslam 2014）を Strang 分割で追加する。CT と整合する形で Ψ（のちの面磁場）も更新し、加熱と台帳を保つ。
- `eta_model` ごとに異方性を保つ。分割すると時間 2 次に留まるので、高次スキームとの組み合わせで精度が落ちる点を明記する。
- **台帳:** RKL2 の係数には負のものがあるので、SSP 型の段の重みは使えない。冷却と加熱は、超ステップ全体の状態差から計算する。
- **η の中央面テーブル:** 超ステップ内で固定するか、段ごとに更新するかを明示して選ぶ。段ごとの更新は MPI 実行で段ごとの `MPI_Allgatherv` になる。誤差と通信量を測って決める。
- **切替条件:** 拡散率が移流率を超えるときのみ RKL2 を使う。それ以外は陽的のまま。閾値は性能と誤差の測定で決める。
- **合格:** 解析解の抵抗減衰（Cartesian と球面）で 2 次。divB が丸め誤差レベル。解像度 1200×256 で実行時間の短縮を測定する。

### WP3.8 平衡の維持

2.3 節の円盤内部ドリフトに対して、well-balanced 法（Käppeli & Mishra 2016 など）を選択肢として調べる。

- **採用条件:** 磁場なし平衡のドリフトを同じ解像度で 10 倍以上改善し、衝撃波試験を悪化させない。満たさなければ不採用として記録する。
- 円盤表面の非収束はこの手法の対象外の可能性が高い。WP1.4 の結果と分けて評価する。

**G3:** 表「スキーム構成 × 問題 × 次数と誤差」を `docs/validation/` に保存する。次を数値で確認する。値は初期の提案で、変更するなら根拠を残す。

- **FV4（Cartesian）:** 2D `oblique_alfven` と `linear_wave` 全モードで、誤差の頭打ちより手前の最後の 2 回の細分化で次数 3.8 以上。
- **面中心流束の構成:** `oblique_alfven`（振幅 0.1、128×64）で L1 誤差が WP0.2 の基準の 1/3 以下。L∞ 次数は基準より 0.5 以上高い。漸近次数を振幅別に明記し、2 次に落ちるならそう書く。
- **円盤問題:** 新スキームを既定にする場合は、ノイズフロアを超える差を根拠にする。

## 9. Phase 4: 3D MHD、並列、I/O（規模 XL）

### WP4.1 3D CT

- WP3.0 の層を φ 方向へ広げ、辺 EMF 3 成分すべてを計算する。UCT は各辺に適用する。
- **合格:** 3D で離散 divB が丸め誤差レベル。`nφ=1` の結果が WP3.0 とビット一致する。`oblique_alfven` 3D で 2D と同等の次数（Felker & Stone は 3D の誤差が定数倍増えることを報告している）。

### WP4.2 3D 球面と極

- φ 方向の流束と幾何ソースを追加する。
- 極の処理は D3 で決める。**極の dt 制約は計算量を桁で左右する**（11 章 WP6.8）。
- 極の面では、1 つの辺に複数の EMF の見積もりが集まる。`E_r` が 1 つの値になるよう平均する処理を実装する。φ+π のセルを ghost にする場合は通信が要るので、`nφ` を偶数に限定する（WP4.3 の分割と整合させる）。
- **合格:**
  - 3D 球面で `v=0, p=一定, B=0` の状態を丸め誤差で保つ。
  - **一様な Cartesian 磁場は曲線座標成分が変化するので、丸め誤差では保てない。** 設計次数で誤差が減ることを確認する。
  - 極を横切る `field_loop` と斜め流で、極付近の誤差と dt の制約を報告する。

### WP4.3 領域分割と通信

- 3D のデカルト分割。デバイス上で pack と unpack を行い、非ブロッキング通信にする。GPU-aware MPI を選択可能に（host 経由も残す）。
- 内部領域と境界領域の計算を分けて、通信と重ねる。
- 共有面と辺の所有権を定める。**分割数によって結果が変わらないこと**を検証する。
- 円盤の中央面テーブルは SF2014 クロージャの中に閉じ込め、他のモデルで通信が発生しないようにする。
- 乱数の初期摂動は、**分割数に依存しないシード**（全体のセル番号から生成）にする。
- **合格:** CPU で 1/2/4/8 rank がビット一致。GPU は同じ分割での再現と、分割間の差が規則 11 の基準内。weak scaling と、既存の 1200×256 の strong scaling を実機で測定して、2.6 節と比較する。weak の格子は GPU のメモリから決める。1 セル 1.5 KB なら 256³ で約 25 GB になり、V100 32 GB ではほぼ上限で、A30 24 GB を超える。まず 128³/GPU から始める。

### WP4.4 I/O と再開

- 並列 HDF5 + XDMF を任意依存で追加する（`PYHMD_HDF5`）。CSV は小規模と回帰用に残す。
- 異なる分割からの再開を、署名を緩めずに実装する。論理配列の順序で保存すれば可能になる。
- Python の `Result` を遅延読み込み対応にする（`h5py` は `[analysis]` の追加依存）。
- 既存の結果読み込みを壊さない（`AGENTS.md`）。

**G4:** 3D ニュートン MHD が上記を満たす。

## 10. Phase 5: SRMHD（規模 L）

GR の前に、平坦時空で変数変換とリーマン解法を固める。

### WP5.1 基本量の回復（con2prim）

- 主方式は Kastaun, Kalinani & Ciolfi 2021 の方式を論文から実装する。解の存在と一意性の証明、精度の上限がある。
- デバイスで動くよう、反復回数の上限付きの囲い込み法にする。RePrimAnd のソースは取り込まない。
- 比較用に Noble et al. 2006 または Newman & Hamlin 2014 も実装する。
- 磁化が高く保存量からの圧力回復が不正確な領域に備え、**エントロピーからの回復を補助に用意する**。切替条件を測定で決め、回数とエネルギー差を台帳に記録する。
- **失敗の扱い:** 黙って隣接値で埋めない。GRMHD の極付近や低密度では失敗が日常的に起こりうるので、段全体の棄却を基本にしてはならない。修復の階層（エントロピー回復、局所 FOFC、台帳に記録した修復）を明示し、段の棄却は最後の手段にする。
- **合格:**
  - (ρ, W, β, σ, v と B の角度, γ=4/3 と 5/3) の格子を掃引し、往復誤差と失敗率の表を作る。範囲は W≤1000、σ≤1e4、β≥1e-6 を目安にする。
  - **許容誤差は ε·E/p に比例させる。** 磁化が極端な角では p/E が 1e-16 付近まで下がり、FP64 では原理的に回復できない。回復可能な領域（ε·E/p ≤ 1e-3 を初期値）で失敗 0、誤差は定数倍以内を目標にする。
  - **往復試験は正しい状態しか入力しない。** 実際の更新で生じる入力を模して、保存量に摂動を加えた入力や、許容領域外の入力も試す。範囲外を検出して報告でき、NaN を出さないこと。
  - 反復回数の分布を報告する。GPU で同じ結果になることを実機で確認する。

### WP5.2 スキーム

- 基本量は ρ, p, ũ^i, B^i。**ũ^i（4 元速度の空間成分）を再構成する**ので、v>c の界面状態が作れない。
- リーマン解法は HLL を最初に作り、次に HLLD（Mignone, Ugliano & Bodo 2009）。HLLD の反復が収束しなければ HLL へ局所的に切り替え、回数を記録する。
- EMF は UCT-HLL。HLLD の流束と UCT-HLL の EMF の組み合わせは過渡的な選択であると明記する。
- **合格:**
  - Komissarov 1999 と Balsara 2001 の衝撃波管で、厳密解（Giacomazzo & Rezzolla 2006）に対する ρ、p、B の L1 誤差が細分化で減る（次数 0.7 以上を目安）。全ケースの誤差を表にする。解の表は独立な実装または公開値から得る。
  - 線形波で次数を実測する。
  - 相対論的な Orszag–Tang と回転子が高磁化で動く。floor の量を報告する。

**G5:** 上記を満たす。

## 11. Phase 6: GRMHD（規模 XL）

### WP6.1 計量

固定された定常時空を対象にする。

- `Minkowski`（直交、球面）、`KerrSchild`、`MKS`、`FMKS`。
- 計量 `g_μν`、`g^μν`、`√-g`、接続 `Γ` を、セル中心、6 面、12 辺で保持する。解析形があれば解析形を使い、なければ数値微分を使う。
- **合格:**
  - `g_μα g^αν = δ` が**軸上の面と辺を除く**全点で丸め誤差レベル（軸では `g_φφ=0` で特異）。
  - 接続は解析形と数値微分の両方の値を単体テストで比較する。
  - 球面座標の Minkowski で、`v=0, p=一定, B=0` が丸め誤差で保たれる。そのために Γ を離散的な `√-g` の差分と整合させる。
  - 一様磁場は丸め誤差では保てないので、設計次数の収束を確認する。

### WP6.2 保存形

Gammie, McKinney & Tóth 2003 の共変形を採用する。

```text
∂t(√-g ρu^t)           + ∂i(√-g ρu^i)                   = 0
∂t(√-g (T^t_ν + ρu^t δ^t_ν)) + ∂i(√-g (T^i_ν + ρu^i δ^t_ν)) = √-g T^κ_λ Γ^λ_νκ
∂t(√-g B^i)            + ∂j(√-g (b^i u^j - b^j u^i))    = 0
```

- **誘導方程式の符号に注意する。** `∇_ν *F^{νi}=0`、`*F^{μν}=b^μ u^ν - b^ν u^μ`、`*F^{ti}=-B^i` から導いた形が上の式で、ニュートン極限で `∂t B = ∇×(v×B)` に一致する。文献の HTML 変換版などに別の並びの表記があるので、そのまま写さず、`v×B` と比較する単体テストを置く。
- 基本量は ρ, u（内部エネルギー）, ũ^i, B^i。`ũ^i = u^i + γ β^i / α`（定義は McKinney & Gammie 2004、Noble et al. 2006 を確認する）。
- **定常・軸対称の Killing ベクトルに対応する `ν=t, φ` のソースは厳密に 0 になる。** 数値で計算せず、コード上で 0 にする。これで全エネルギーと全角運動量（φ 成分）が流束のみで保存され、既存の台帳の考え方をそのまま適用できる。座標変換（MKS、FMKS）がこれを保つ条件を文書化し、テストする。
- CT は `√-g B^i` を面に置き、辺 EMF で更新する。

### WP6.3 Floors と台帳

- 公開されている設定を出発点にする（Porth 2019 の提案値 `ρ_fl = 1e-5 r^-3/2`、`p_fl = (1/3)·1e-7 r^-5/2`、Athena++ の `σ<100`、`β>1e-3`、Γ<50）。すべて設定可能にして、結果に記録する。
- 質量とエネルギーの注入は、drift frame または normal observer frame から選ぶ（Ressler et al. 2017 など）。両方を実装して比較する。
- 注入した質量、エネルギー、運動量を種類ごとに台帳へ記録する。**FOFC（WP3.5）を GR でも使い、floor への依存を減らす**（AthenaK の報告を参考に）。

### WP6.4 リーマン解法と EMF

- まず HLL。次に、面ごとの局所直交系へ変換する HLLD（White, Stone & Gammie 2016。同論文が引く Pons et al. 1998、Antón et al. 2006 も確認する）。ホライズン内部でも normal observer の系を使えば有効である。
- **波速:** 計量を含む磁気音波の速度の計算を、CFL、リーマン解法、CT の風上化で共通の関数にする。座標速度であることと、ホライズン内部で内向きに偏ることを単体テストで確認する。
- 辺の EMF は最初に GS05 型の CT を実装し（`E_i` は `v^i = u^i/u^t` と `√-g B^i` から作る）、UCT-HLL は比較実験にする。
- 相対論版 UCT-HLLD は本計画の範囲外（Phase 7 の研究課題）。

### WP6.5 境界

- **内側:** ホライズン内部に打ち切る。Porth 2019 の実績では a=0.9375 で r_in=1.05〜1.25、Athena++ は「最低解像度で 1 セル丸ごとホライズン内」。r_in を動かしても外部解が変わらないことを試験で確かめる。
- **極:** WP4.2。
- **外側:** 流出境界。流入を拒否する。
- 境界の面を横切る流束を台帳へ積分する（Mdot、Edot、Ldot、Φ）。**Porth の指標はホライズン r_h での値なので、計算領域の境界 r_in<r_h とは位置が違う。** r_h に最も近い面を指定して別に積算し、補間の規則を決めて記録する。

### WP6.6 初期条件と API

- `michel`、`gammie_inflow`、`bz_monopole`、`fm_torus`（Fishbone & Moncrief 1976）をプリセットにする。
- `Config.model="grmhd"`、`GridConfig.geometry` に計量を追加し、`spin`、座標パラメータ、floor の設定を型付きで受け取る。未対応の組み合わせは拒否する。
- `pyhmd.diagnostics.grmhd` に Porth 2019 の指標（下記）を実装する。

| 項目 | 値 |
|---|---|
| スピン、断熱指数 | a=0.9375、γ=4/3 |
| トーラス | FM、r_in=6M、r_max=12M |
| 磁場 | `A_φ ∝ max(ρ/ρ_max − 0.2, 0)`、`2 p_max/(B²)_max = 100`（極大の位置は一致しなくてよい） |
| 摂動 | `p* = p(1+X_p)`、X_p は [−0.02, 0.02] の一様乱数 |
| 領域 | r∈[r_h, 50]、θ∈[0, π]、φ∈[0, 2π]（ガイドライン） |
| 解像度 | 96³、128³、192³（できれば上） |
| 時間 | t=10000M まで。平均区間 t∈[5000M, 10000M] |
| 指標 | ホライズンでの Mdot、Φ_BH、Ldot、Edot。`φ = Φ_BH/√Mdot`、`Ldot/Mdot`、`(Edot−Mdot)/Mdot`。論文の式 13〜19 に従う |
| 殻平均 | ρ, p, u^φ, √(b·b), β⁻¹（θ∈[π/3, 2π/3]） |

**合格（G6）:** 論文の表 2 の各解像度の値域と比較した表を出す。**コード間の散らばりは小さくない。** 192³ でも max/min は Mdot 平均で 1.77、φ 平均で 2.78、(Edot−Mdot)/Mdot 平均で 1.41、スケールハイト H/R は全コードで 0.25〜0.3 と報告されている。
判定は次の 3 つで行う。

1. 各指標が同じ解像度の公開値域に入るか。
2. 解像度を上げたとき、値域に近づくか。
3. シードを変えた 3 本以上の揺らぎと比べて、差に意味があるか。

**値域は広いので、入っただけでは正しさの証明にならない。** 表には「値域内」とだけ書き、「検証済み」とは書かない。値域外なら原因調査を優先する。

**計算量の概算（重要）:** 192³ は約 710 万セル。1 セル 1.5 KB なら約 11 GB。実行時間は極付近の dt で桁が変わる。

ホライズン付近の極のセルは φ 方向の幅が極端に狭く、光速で dt を見積もると、一様 θ で 1.4e-4M 程度、MKS h=0.3 でも 3〜4e-4M 程度になる。強い極の拡大（FMKS など）を使っても 5e-3M に届くかは未確認である。

| dt [M] | 1 本のステップ数 | 4 V100（3600 万セル・ステップ/秒、GR の負荷 5〜10 倍を仮定） |
|---|---|---|
| 5e-3 | 2e6 | 23〜46 日 |
| 1e-3 | 1e7 | 114〜228 日 |
| 4e-4 | 2.5e7 | 285〜569 日 |

すべて仮定を含む粗い値で、複数シードや低解像度の分は含まない。**極の処理（D3）を決める前に、WP6.1 の計量表で実際の dt を計算する。** 極付近で dt∝N⁻² になるので、解像度を下げると大きく減る（96³ は 192³ の約 1/32）。まず 96³ で性能を測り、minami に計算資源を相談する（D4）。

## 14. 主なリスク

| リスク | 対策 |
|---|---|
| Phase 2 の規模が膨らみ、ビット一致が崩れる | 小さいコミットと毎回の migration 比較。崩れたら戻す |
| 高次スキームが円盤問題で不安定、または効果がない | 旧スキームを残す。WP0.4 のノイズフロアで判定する |
| 極の dt で本番計算が現実的な時間に収まらない | D3 を早期に計算で判断する。96³ から始める。解決しなければ G6 の範囲を minami と見直す |
| 内側境界の問題がスキーム変更で隠れる | Phase 1 を先に行う。スキーム比較で境界を同じにする |
| GPU のコンパイルとレジスタ圧迫 | 成分別カーネル、TU 分割、`PYMHD_KERNEL_STATS` で監視 |
| HLLD や con2prim の失敗が局所から全域に波及 | フォールバックの階層化と、失敗回数の記録 |
| GRMHD の乱流で「合っている」かの判定が難しい | 解析解のある試験を先に通す。Porth の値域と比較し、断定しない |
| floor が結果を支配する | 台帳で量を見て、floor の設定を変えた感度試験を行う |
